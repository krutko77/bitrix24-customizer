# Передача проекта

## Снимок передачи

- **Дата:** 2026-11-25 (конец шестой сессии)
- **Проект:** помощь в настройке Битрикс24 ЕС Транс (облако, тариф «Профессиональный»): REST, вебхуки, БП, UF, смарт-процессы. В оболочке проектов — статус «РАБОЧИЙ», раздел «АГЕНТЫ», тип «АГЕНТ» (`.portal-meta.json`).
- **Статус:** база знаний готова, опись портала и разбор интеграции с 1С сняты (только чтение). Вебхук отключён сотрудником, `B24_WEBHOOK_URL` в `.env` пуст. Задачи A (номер счёта → Заказ) и B (папка заказа на Диске) закрыты. **Открыта задача C:** в БП 682 (расчёт маржи ПЕРЕВОЗКИ) сотрудник сам внёс правку — новое числовое поле 0/1 «все заявки привлечённых перевозчиков заполнены» для робота на стадии (экспорт `bp-682.bpt`, коммит `bd03ac0`); структуру сверили, **на портале результат не проверен**. В портал мы ничего не вносили.
- **Что прочитать первым:** `docs/state.md`; для задачи C — `docs/local-task-carrier-flag.md` (локальный, в git его нет); по закрытым — `docs/local-task-invoice-number.md`, `docs/local-task-order-folders.md`.
- **Главное открытое:** результат проверки задачи C (0/1, нулевая сумма, старые карточки, гонка робота и 682 ~8 с); убрать старое поле «удалить» из шага «Очистка полей» БП 682. Необязательно: вопросы из `docs/gaps.md`; судьба `bp-682/910/932.bpt` в публичном репозитории; чистка `/tmp` и журналов сессий — по решению сотрудника.
- **Первый шаг:** спросить сотрудника, чем закончилась проверка БП 682. Для новой задачи по порталу — новый вебхук (создаёт сотрудник, скоупы под задачу, сначала чтение); правки БП сотрудник вносит сам, мы готовим инструкцию или сверяем по скриншотам/экспорту `.bpt` (`scripts/bpt-dump.py`, `scripts/bpt-tree.py`); запись в портал — только после отдельного «да».
- **Git:** ветка `main`, `origin` = https://github.com/krutko77/bitrix24-customizer.git (**публичный**); снимки через `scripts/snapshot.sh` (коммит + автоматический push). Перед снимком проверять diff на секреты; названия бизнес-объектов и коды полей портала — только в `docs/local-*.md`.
