# 00. Что можно кастомизировать в облачном Битрикс24

Источник: [developing-with-rest-api.md](rest-docs/developing-with-rest-api.md), [local-integrations/](rest-docs/local-integrations/index.md), [settings/cloud-and-on-premise/](rest-docs/settings/cloud-and-on-premise/index.md). Статус: *по документации*.

## Главное ограничение облака

В облаке **нет доступа к серверу и файлам портала**. Поэтому:

- **нельзя** править PHP-код ядра, класть свои файлы в `/local/` или `/bitrix/php_interface/`, подключать свои модули, писать обработчики событий на PHP, использовать API D7 (`\Bitrix\Main\...`) «внутри» портала;
- **можно** работать только снаружи — через **REST API**, вебхуки и приложения, плюс штатные настройки и конструкторы портала.

Это значит: основной инструментарий для ЕС Транс — **REST API + встроенные средства** (роботы, бизнес-процессы, смарт-процессы, пользовательские поля, формы, отчёты). D7/Framework — справочный материал, см. [10-d7-and-bitrix-framework.md](10-d7-and-bitrix-framework.md).

## Уровни кастомизации (от простого к сложному)

| Уровень | Что это | Код нужен? | Где подробнее |
|---|---|---|---|
| 1. Штатные настройки | Права, структура, воронки и стадии CRM, поля, шаблоны, смарт-процессы | Нет | справка helpdesk.bitrix24.ru (ссылки на страницах разделов) |
| 2. Встроенная автоматизация | Роботы и триггеры CRM, бизнес-процессы (конструктор), умные сценарии, CRM-формы | Нет | [06-automation-events.md](06-automation-events.md) |
| 3. Входящий вебхук | Внешний скрипт/сервис вызывает методы REST от имени сотрудника | Да, любой язык | [01-access-auth-webhooks.md](01-access-auth-webhooks.md) |
| 4. Исходящий вебхук | Битрикс24 шлёт событие (создана сделка…) на ваш URL | Да, нужен публичный HTTPS-обработчик | [06-automation-events.md](06-automation-events.md) |
| 5. Локальное приложение | Приложение, установленное только на ваш портал: интерфейс во фрейме, события, роботы своих типов, встройка в карточки | Да | [07-apps-and-placements.md](07-apps-and-placements.md) |
| 6. Тиражное приложение | Для Маркетплейса, ставится на разные порталы | Да + партнёрство | вне задач ЕС Транс (см. [market/](rest-docs/market/index.md)) |

**Правило выбора:** брать самый низкий уровень, который решает задачу. Например, «при переводе сделки на стадию — создать задачу» делается роботом (уровень 2) без кода; «после оплаты в 1С обновить сделку» — входящим вебхуком (3); «показать во вкладке сделки данные из своей системы» — локальным приложением с placement (5).

## Что нужно для работы REST API

- Платный тариф (у ЕС Транс — «Профессиональный») **и** доступ к REST API по подписке *BitrixGPT + Маркетплейс* (или пробный режим «Включить демо»). Подробности — [01-access-auth-webhooks.md](01-access-auth-webhooks.md).
- Права: REST выполняет всё **от имени пользователя**, не шире его прав в интерфейсе; дополнительно ограничивается `scope`.
- Ограничения облака: лимиты частоты и ресурсоёмкости — [03-limits-and-errors.md](03-limits-and-errors.md).

## Что REST умеет (карта возможностей)

Основные группы (подробнее по каждой — в соответствующих файлах):

- **CRM**: лиды, сделки, контакты, компании, предложения, счета, смарт-процессы, воронки/стадии, товарные позиции, реквизиты, дела, таймлайн, дубли, CRM-формы, генератор документов.
- **Автоматизация**: роботы приложений, действия БП, запуск БП, триггеры, события, офлайн-события.
- **Задачи и проекты**: `tasks.*`, чек-листы, учёт времени, рабочие группы, Scrum, потоки.
- **Люди**: пользователи, подразделения (`department.*`, новый `humanresources.*`), учёт рабочего времени.
- **Коммуникации**: чаты и уведомления, чат-боты, открытые линии и коннекторы, телефония, SMS-провайдеры, почта.
- **Данные и файлы**: Диск, универсальные списки, инфоблоки, хранилище данных (`entity.*`), форум.
- **Встраивание в интерфейс**: placement (виджеты), пользовательские типы полей, левое меню.
- **Прочее**: календарь, КЭДО/подписание, интернет-магазин и каталог, сайты (Landing), BI-коннектор, онлайн-запись.

Полная карта страниц — [reference/methods-index.md](reference/methods-index.md).

## Чего в облаке нет или нужна оговорка

- Методы «только для коробки» (собственные методы REST, свой провайдер авторизации): [settings/cloud-and-on-premise/on-premise/](rest-docs/settings/cloud-and-on-premise/on-premise/index.md) — к облаку **не относятся**.
- Часть методов работает **только в контексте приложения** и недоступна вебхуку: `placement.bind`, часть телефонии, часть чат-ботов. Для них нужно локальное приложение.
- Исходящий вебхук недоступен на демо-режимах (по документации).
