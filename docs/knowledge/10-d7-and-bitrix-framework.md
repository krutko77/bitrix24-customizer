# 10. API D7 и Bitrix Framework: что это и почему почти не применимо в облаке

Статус: **обзор и карта источников**. Содержимое разделов D7 и Bitrix Framework в базу не копировалось (в отличие от REST-документации); страницы по существу в этой сессии не читались. Доступность адресов проверена 2026-11-06 (HTTP 200).

## 1. Суть

| Понятие | Что это | Где работает |
|---|---|---|
| **Bitrix Framework** («1С-Битрикс: Управление сайтом»), ядро PHP | Продукт и платформа, на которой построены «коробочные» продукты 1С-Битрикс и Битрикс24 в коробке | На вашем сервере (коробка) |
| **API D7** | Современное объектно-ориентированное ядро Bitrix Framework (пространства имён `Bitrix\Main\…`, ORM, события, контроллеры). Документация: классы, методы, события, константы | PHP-код **внутри** установки на сервере: модули, компоненты, обработчики событий ядра, агенты |
| **Старое ядро** | Процедурное API (`CModule`, `CIBlockElement`, `AddEventHandler` и др.), существует рядом с D7 | То же |
| **REST API** | Внешний HTTP-интерфейс к данным и функциям | Облако и коробка |

## 2. Что это значит для облачного Битрикс24 ЕС Транс

Облачная версия — это сервис: **нет доступа к файловой системе и серверу, нельзя ставить PHP-модули, править ядро, писать `init.php`, обработчики событий ядра (`EventManager`), агенты, компоненты, ORM-запросы к БД.** Поэтому D7 и ядро Bitrix Framework **не являются** инструментом кастомизации облачного портала; знания о них нужны лишь для (а) понимания, откуда в REST берутся термины и поведение (инфоблоки, UF, события, ORM-подобные фильтры), (б) чтения чужих примеров из коробочной версии и переноса их идей в REST, (в) возможного будущего перехода на коробку.

Что вместо этого доступно в облаке:

| Нужно (в коробке через D7/ядро) | В облаке (через что) |
|---|---|
| Обработчик события ядра (`OnAfterCrmDealUpdate`) | Исходящий вебхук / `event.bind` → [06](06-automation-events.md) |
| Агент по расписанию | Внешний планировщик + REST; либо робот/БП по сроку |
| Компонент, кастомная страница | Локальное приложение, placement → [07](07-apps-and-placements.md) |
| ORM-запрос к таблицам | `crm.item.list`, `*.list`, `batch`; для аналитики — BI-коннектор → [02](02-rest-requests.md), [03](03-limits-and-errors.md) |
| Новое свойство/поле | UF через REST → [05](05-user-fields.md) |
| Кастомное действие БП | Робот/действие приложения → [06](06-automation-events.md) |
| Правка шаблона, хуки в шаблоне | Недоступно; только настройки интерфейса и placement |

> Если в запросе встречается PHP-код с `\Bitrix\Main\…`, `CModule::IncludeModule`, `AddEventHandler` и т. п., он предназначен для коробки и в облаке не заработает без переписывания на REST.

## 3. Карта источников dev.1c-bitrix.ru (адреса проверены 2026-11-06)

| Раздел | Адрес | Содержание |
|---|---|---|
| API D7 | https://dev.1c-bitrix.ru/api_d7/ | Классы и методы ядра D7 (`Bitrix\Main`, модули), события |
| Справочник старого ядра | https://dev.1c-bitrix.ru/api_help/ | Классы и функции Bitrix Framework (процедурное API, компоненты, события) |
| Учебные курсы | https://dev.1c-bitrix.ru/learning/ | Курсы для разработчиков и администраторов (в т. ч. `/learning/course/`) |
| Документация REST | https://dev.1c-bitrix.ru/rest_help/ → **перенаправляет на** https://apidocs.bitrix24.ru/ | Актуальный справочник REST; его исходники — зеркало, см. [sources.md](sources.md) |
| Помощь пользователям | https://helpdesk.bitrix24.ru/ | Настройка портала через интерфейс (роботы, CRM, права) |

Полезны для облака: `apidocs.bitrix24.ru` (REST) и `helpdesk.bitrix24.ru` (настройки без кода). D7 и `api_help` — по необходимости, только для чтения как справочник.

## 4. Как работать с этим разделом

- Если нужен D7-класс или поведение коробки — открывать нужную страницу точечно по ссылке выше, не копировать раздел целиком.
- В ответе пользователю явно отмечать, если решение из примера D7 к облаку не применимо, и предлагать REST-эквивалент.
- Возможность работы с коробкой/сервером ЕС Транс не выяснена — вопрос в [../gaps.md](../gaps.md).
